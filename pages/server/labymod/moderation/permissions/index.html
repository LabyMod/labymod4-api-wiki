    Permissions

    The PermissionPacket is a client-bound packet that allows servers to deactivate and/or activate certain features for their Laby Client players.

    What permissions are available?

    All permissions available in Laby Client itself can be found as constants in the Permission class, integrations may also create their own permissions.
    Creating custom permissions is possible via Permission.of(String).

    Sending the Packet

    The packet can either be sent via the LabyModPlayer object of the player, or directly via the LabyModProtocol.

    The packet requires the type StatedPermission which can be obtained by calling either Permission#allow or Permission#deny. So for example Permission.CHAT_AUTOTEXT.deny() would disable the chat autotext feature.

    Via LabyModPlayer

    // Create a List of permissions (array is also possible)
List<Permission.StatedPermission> permissions = new ArrayList<>();

// Add all permissions you want to allow and/or deny
permissions.add(Permission.CHAT_AUTOTEXT.deny());

// Get the LabyModPlayer
LabyModPlayer labyModPlayer = LabyModProtocolService.get().getPlayer(uniqueId);

// Send the permissions
labyModPlayer.sendPermissions(permissions);

    Via the LabyModProtocol

    // Create a List of permissions (array is also possible)
List<Permission.StatedPermission> permissions = new ArrayList<>();

// Add all permissions you want to allow and/or deny
permissions.add(Permission.CHAT_AUTOTEXT.deny());

// Get the LabyModProtocol
LabyModProtocol labyModProtocol = LabyModProtocolService.get().labyModProtocol();

// Send the packet
labyModProtocol.sendPacket(uniqueId, new PermissionPacket(permissions));

    Disabling Features

    Besides the permissions above, a server can turn off a feature of the Laby Client by its id. Deny the permission feature_<id>, for example feature_fullbright. Allow it again to give the feature back.

    labyModPlayer.sendPermissions(Permission.of("feature_fullbright").deny());

    The player's own setting stays as it is. The feature counts as off until the server allows it again or the player leaves, and its settings show that the server disabled it.

    • Features are allowed by default. You only need to send the ones you want to deny.
    • A denial lasts until the player leaves the server. Unlike the permissions above, it survives subserver switches, so you send it once.
    • Some features have parts with their own switch, like the cinema bars of Zoom. Deny feature_<partId>, e.g. feature_cinema_bars, to turn off only that part. Denying the feature turns off all of its parts.
    • Features of addons carry the addon's namespace: feature_<namespace>:<id>.
    • If your server also uses Apollo, a feature stays off as long as either of them disables it.
